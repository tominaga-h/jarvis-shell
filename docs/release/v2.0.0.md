# v2.0.0 リリースノート

> AI Brain を OpenAI 専用実装からプロバイダ中立アーキテクチャへ全面刷新したメジャーリリースです。OpenAI に加えて **Anthropic (Messages API)** と **OpenCode Zen / Go** をネイティブサポートし、`[ai].provider` の 1 行でバックエンドを切り替えられるようになりました。あわせて AI ストリーミング中の進捗表示、起動バナーへのプロバイダ / モデル表示、`source` によるプロバイダのホットスワップに対応しています。
>
> **破壊的な設定変更はありません。** v1.15.6 の `~/.config/jarvish/config.toml` は一切変更せずに従来と同じ動作をします（`provider` の既定値は `"openai"`、`model` の既定値は `"gpt-4o"` のままです）。

## 主な機能

### マルチプロバイダ AI 対応 — v2.0.0

`[ai].provider` で AI バックエンドを選択できるようになりました。指定できる識別子は次の 4 つです。

| `provider` | バックエンド |
| --- | --- |
| `"openai"`（既定） | OpenAI Chat Completions API |
| `"anthropic"` | Anthropic Messages API（ネイティブ実装） |
| `"opencode-zen"` | OpenCode Zen |
| `"opencode-go"` | OpenCode Go |

```toml
[ai]
provider = "anthropic"
model = "claude-sonnet-4-5"
```

未知の値を指定した場合は起動時に、サポートされているプロバイダ名を列挙したエラーを表示します。

> **注意:** `model` の既定値はプロバイダに依存せず常に `"gpt-4o"` です。`provider` を切り替えたときは `model` も必ずそのプロバイダのモデル識別子へ変更してください。`provider = "anthropic"` だけを書いて `model` を省略すると、`gpt-4o` が Anthropic へ送信されて失敗します。

### `[ai]` の新しい設定項目 — v2.0.0

`provider` / `max_tokens` / `base_url` / `api_key_env` を追加しました。いずれも省略可能で、省略時はプロバイダに応じた既定値へ解決されます。

| 項目 | 説明 | 既定値 |
| --- | --- | --- |
| `provider` | 使用する AI プロバイダ | `"openai"` |
| `max_tokens` | 生成する最大トークン数 | Anthropic: `16384` / その他: `8192` |
| `base_url` | API エンドポイントの上書き（プロキシ・テスト用途） | Anthropic: `https://api.anthropic.com`<br>Zen: `https://opencode.ai/zen/v1`<br>Go: `https://opencode.ai/zen/go/v1` |
| `api_key_env` | API キーを読み込む環境変数名の上書き | プロバイダ既定の変数（下記） |

### プロバイダごとの API キー環境変数 — v2.0.0

`api_key_env` で上書きしない限り、プロバイダに応じて次の環境変数から API キーを読み込みます。

```bash
export OPENAI_API_KEY="sk-..."        # provider = "openai"
export ANTHROPIC_API_KEY="sk-ant-..." # provider = "anthropic"
export OPENCODE_API_KEY="..."         # provider = "opencode-zen" / "opencode-go"
```

### AI ストリーミング中の進捗表示 — v2.0.0

AI 応答の待ち時間中に、経過秒数・受信バイト数・チャンク数をスピナー上に表示するようになりました。

```
🤵 ⠹ Buffering... 3s elapsed, 1024 bytes (17 chunks)
```

接続待ち〜最初のトークンまでは `Thinking...`、ストリーム終端の Markdown 整形中は `Rendering...` を表示します。表示更新は 100ms でスロットルされ、完了時には行をクリアして AI の応答のみが残ります。

### 起動バナーにプロバイダ / モデルを表示 — v2.0.0

バージョン行の下に、現在使用中のプロバイダとモデルを表示します。

```
provider: openai
model: gpt-4o
```

API キーが未設定で AI クライアントが初期化されていない場合は、従来どおりこの 2 行を表示せず `AI module offline` を報告します。

### `source` によるプロバイダのホットスワップ — v2.0.0

`source ~/.config/jarvish/config.toml` で、シェルを再起動せずにプロバイダを切り替えられるようになりました。`model` / `provider` / 実効 `base_url` / 実効 `api_key_env` のいずれかが変化した場合に AI クライアントを再構築し、それ以外の変更（`max_rounds`、`temperature`、`max_tokens` など）は従来どおり軽量な設定更新のみを行います。

- 起動時に API キーが未設定で AI が無効だった場合も、キーを設定して `source` すればその場で有効化できます
- クライアントの再構築に失敗した場合は警告ログのみを出して既存のクライアントを維持するため、`source` 自体が失敗することはありません
- `source` のサマリー出力の `[ai]` セクションに `provider` / `max_tokens` / `base_url` / `api_key_env` の 4 行を追加しました（`max_tokens` などは解決後の実効値を表示）

## バグ修正

- OpenCode の User-Agent テストが `jarvish/1.15.6` をハードコードしており、`Cargo.toml` のバージョン更新に追従できていなかった問題を修正（`env!("CARGO_PKG_VERSION")` を参照するよう変更）

## 内部改善

### プロバイダ中立バックエンドへの刷新

AI クライアントが `async-openai` の型に直接依存していた構造を解体し、プロバイダ中立の抽象層 `src/ai/provider/` を新設しました。

- `enum AiBackend { OpenAiCompat, Anthropic, OpenCode }` によるディスパッチ。各バックエンドは `create_stream(ChatRequest)` のみを担う
- 中立型 `ChatMessage` / `ChatRequest` / `ChatChunk` / `ToolCall` / `ToolSpec` を `provider/types.rs` に定義
- `src/ai/stream.rs` をこの中立型ベースへほぼ全面的に書き換え

### Anthropic Messages API のネイティブ実装

- `reqwest` ベースで `POST {base_url}/v1/messages` を呼び出し、`x-api-key` と `anthropic-version: 2023-06-01` ヘッダを送信（`provider/anthropic.rs`）
- Anthropic 固有のリクエスト整形（`provider/anthropic/request.rs`）— `system` をトップレベルへ集約し、`tool_result` は後続の user メッセージへまとめる。現行の Claude モデルが拒否するため `temperature` は送信しない
- 独自の SSE パーサ（`provider/anthropic/sse.rs`）

### OpenCode Zen / Go 対応

- OpenAI 互換のリクエスト形式を流用しつつ、`User-Agent: jarvish/{version}` を送信（`provider/opencode.rs`）
- 仕様に準拠しない末尾の cost チャンクを抑制する `OpenCodeStream` ラッパを実装

### テストの追加

- 統合テスト `tests/anthropic_mock.rs`（`axum` によるモックサーバ）、`tests/opencode_zen_compat.rs`
- Anthropic SSE のフィクスチャ 5 本（`tests/fixtures/anthropic_sse/` — 単純テキスト / ping 混在 / エージェントループ / refusal / エラー応答）
- `src/ai/client/tests.rs` にプロバイダ選択と既定値解決のテスト、`src/config/tests.rs` に旧 config の後方互換パースのテストを追加
- dev-dependency に `axum 0.8` を追加

## 互換性

- **設定の破壊的変更はありません。** 追加された 4 項目はすべて省略可能で、`provider` の既定値が `"openai"`、`model` の既定値が `"gpt-4o"` のままであるため、v1.15.6 の設定ファイルはそのまま従来と同じ動作をします。設定キーの削除・改名、CLI フラグの変更もありません
- **挙動の変更が 1 点あります:** すべての AI リクエストに `max_tokens` が付与されるようになりました（v1.15.6 では未指定でした）。既定値は OpenAI / OpenCode で `8192` のため、非常に長い応答が従来より短く打ち切られる可能性があります。必要な場合は `[ai].max_tokens` で引き上げてください
- 表示上の変更として、ファイル操作スピナーの絵文字が `📖` / `📝` / `🔧` から `🤵` へ統一されました

## 対応プラットフォーム

- macOS (aarch64 / x86_64)
- Linux (x86_64)

## 既知の制限

- Windows は未対応
- AI 機能の利用には、選択したプロバイダの API キーが必要（`OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `OPENCODE_API_KEY`）
- `model` の既定値はプロバイダに依らず `"gpt-4o"` のため、プロバイダを変更する場合は `model` も明示的に指定する必要がある
- carapace 外部補完には別途 `carapace` バイナリのインストールが必要
- zsh ブリッジには `zsh` の実行環境が必要
