# v1.15.4 リリースノート

> 補完まわりの不具合を集中的に修正したリリースです。v1.15.1〜v1.15.4 の内容をまとめて公開しています。外部補完が担当するコマンドで誤ったパス補完が表示される問題、`cd` に補完デーモンが追従しない問題、パイプ後段でエイリアスが展開されない問題を修正し、あわせて補完デーモンの残骸ファイルを起動時に自動で掃除するようになりました。

## 主な機能

### 補完デーモンの残骸ファイルを起動時に自動掃除 — v1.15.3

補完デーモンが書き出す一時スクリプト `.daemon_init.<pid>.<random>.zsh` は、正常な終了経路（shutdown / `Drop` の reap）では削除されますが、`SIGKILL`・OOM killer・電源断など reap を経ない終わり方をするとファイルだけが残ります。1 個あたり数 KB と小さいものの、放置するとブリッジディレクトリに堆積します（実環境で 237 個の残骸を確認）。

あわせて `compinit` のリネーム残骸（`.zcompdump.<host>.<pid>`）も掃除します。`compinit` はダンプ更新時に一時ファイルへ書き出してから本来の名前へ `mv` するため、その途中で落ちると一時ファイルだけが残ります（実環境で 25 個を確認）。

- 掃除はシェル起動直後のデーモン事前ウォームアップ（バックグラウンドスレッド）で 1 回だけ実行し、UI スレッドを一切ブロックしない
- init スクリプトはファイル名から pid を取り出し `kill(pid, 0)` で生存確認し、既に存在しないプロセスのものだけを削除する。自分自身の pid・生存中の pid・命名規則に合致しないファイル（`.zshrc` 等）は対象外
- 完成品のキャッシュ本体（`.zcompdump`）は削除しない（残骸ではなく有効なキャッシュであり、消すと次回の `compinit` が全補完関数を読み直して起動が遅くなるため）
- 対象はブリッジディレクトリ配下のみで、ユーザー自身の対話 zsh が作る `~/.zcompdump` には一切触れない

### 非対話 (`-c`) 実行のコマンドを履歴に記録しない — v1.15.1

nvim 等の外部ツールがファイル glob 展開のために `jarvish -c "..."` を非対話実行すると、その一時コマンドが履歴（上下矢印キーの履歴補完）に混入していました。bash/zsh と同様に、非対話単体実行は履歴の対象外としました。設定項目は追加せず、常に有効な固定挙動です。

`rc.jsh` / `[startup].commands` / `source` は元々履歴記録の経路を通らないため影響ありません。

## バグ修正

- 外部補完が担当するコマンドで、無関係なパス補完が表示されてから正しい候補に入れ替わる問題を修正 — v1.15.4
  - `tmuxinator <TAB>` がまず `CLAUDE.md` / `Cargo.lock` / `docs/` といったカレントディレクトリのファイル一覧を表示し、しばらくしてから本来のサブコマンド補完へ切り替わっていた
  - 原因は `PathProvider::provide` が無条件で `Some(...)` を返すこと。外部補完プロバイダがタイムアウト・失敗して `None` を返すと、プロバイダ連鎖がそのまま `PathProvider` へ落ち、「答えられなかった」が「パス補完が正解」にすり替わっていた
  - `CompletionProvider` に `is_responsible()` を追加し、担当プロバイダが `None` を返した時点で以降のプロバイダを呼ばずに空候補で確定するようディスパッチを変更
  - 副次的な効果として、carapace と zsh ブリッジでタイムアウト予算が加算される問題（最悪 2.5 秒の UI フリーズ）も解消
- 上記修正による、`tmuxinator <TAB>` が候補ゼロ（`NO RECORDS FOUND`）になる回帰を修正 — v1.15.4
  - carapace は内蔵 spec を持つコマンドしか答えられず、spec が無いコマンドでは正常終了しつつ空の出力を返すため、「担当外なので次に譲る」を「責任者だが失敗した」と誤って申告していた
  - 「責任者を名乗れるのは後ろに誰もいないプロバイダだけ」という原則に沿って carapace の `is_responsible` を常に `false` にし、zsh ブリッジへ確実に繋がるようにした
- 補完候補に「現在のディレクトリに存在しないファイル」が混入する不具合を修正 — v1.15.2
  - 常駐 zsh 補完デーモンは spawn 時点の作業ディレクトリを継承したまま生き続けるため、jarvish 側の `cd` が届かず、`_files` / `_path_files` 等が jarvish の起動ディレクトリを基準に相対パスを解決していた
  - 補完リクエスト送出の直前に jarvish の現在の cwd と突き合わせ、食い違う場合のみデーモンへ移動指示を送る `sync_cwd()` を追加（無変化なら何も送らないため常駐デーモンの利点を失わない）
  - パスはシングルクォートで囲って渡し、空白・`$`・グロブを含むディレクトリ名も安全に扱う
- パイプ/コネクタの各セグメント先頭でエイリアスを展開するよう修正 — v1.15.1
  - `cat x | grep y` のようにパイプ後段のコマンドがエイリアスでも展開されなかった（`&&` `||` `;` の 2 番目以降のセグメントも同様）
  - `|` `&&` `||` `;` で分割した各セグメント先頭にエイリアスを適用する方式へ変更。クォート内や `$(...)` 内の区切り文字は境界として扱わず、リダイレクト（`>` `>>` `<`）もセグメント境界にしない

## 内部改善

- バイト範囲付きトークナイザ `split_quoted_spans` を新設し、トークナイザ実装を一本化（`src/engine/expand/quote.rs`）
- 補完プロバイダのディスパッチを `find_map` から `dispatch_providers()` へ置き換え、tri-state（担当・非担当・失敗）の契約を明確化
- zsh ブリッジ統合テストをブリッジディレクトリと `HOME` ごと一時ディレクトリへ隔離し、開発者のローカル環境に依存しないよう修正
- carapace 統合テストの負荷起因フレークをタイムアウト延長で解消

## 対応プラットフォーム

- macOS (aarch64 / x86_64)
- Linux (x86_64)

## 既知の制限

- Windows は未対応
- AI 機能の利用には OpenAI API キーが必要
- carapace 外部補完には別途 `carapace` バイナリのインストールが必要
- zsh ブリッジには `zsh` の実行環境が必要
